# AgentMaster — Agent Context

## Overview
Meta-orchestrator for AI coding agents. One skill (`/agent-master`) routes all tasks to the right combination of installed skills across caveman (output compression), superpowers (dev workflow), claude-skills (domain expertise), and curated tactical libraries (impeccable, anthropic-official, wshobson, davila7). Supports 11 platforms via auto-generated platform files.

## Stack
- **Language**: Bash (scripts), Node.js (Tool-Stack-Reference generators)
- **Format**: SKILL.md files with YAML frontmatter + markdown body
- **Platforms**: Claude Code, Cursor, Windsurf, Cline, Codex, Gemini CLI, Antigravity, OpenCode, Augment, Aider, GitHub Copilot

## How to Run / Build / Test
```bash
# Add/edit a skill
vim skills/agent-master/SKILL.md

# Regenerate all platform files after skill changes
bash scripts/convert.sh --all

# Fast local dev loop (skip commit+push+update; writes a .dev marker)
bash scripts/dev-sync.sh          # push working tree -> live install
bash scripts/dev-sync.sh --off    # resume normal auto-update

# Run tests (CI runs this + shellcheck --severity=error)
bash tests/smoke.sh

# Install to Claude Code
bash install.sh

# Install to a specific platform
bash scripts/install-platform.sh cursor

# Update all dependency skills (caveman, superpowers, claude-skills, claude-mem,
# impeccable, anthropic-official, wshobson, davila7)
bash scripts/update.sh
```

## Agent-Specific Notes

### What to avoid
- **Never edit platform files directly** (`.cursor/`, `.windsurf/`, `.clinerules/`, CONVENTIONS.md, copilot-instructions.md) — they're regenerated by `convert.sh` and changes will be overwritten
- **Never run `convert.sh` as aider/copilot only** mid-session — it truncates and rewrites the whole aggregate file; run `--all` for consistency
- **Don't move hub/*.md files** — RULES.md references exact paths

### Sensitive areas
- `scripts/update.sh` contains GitHub repo URLs for dependencies — these are public repos but treat as config, not logic
- `Tool-Stack-Reference/master-hub.html` is gitignored (large file, source data)

### Known gotchas
- After editing `skills/agent-master/SKILL.md`, must run `bash scripts/convert.sh --all` OR the 8 platform-specific files will be stale
- `scripts/update.sh` uses `set -e` — any non-subshelled `cd` that fails will silently put subsequent commands in the wrong directory. Fixed to use `git -C` pattern
- `Tool-Stack-Reference/hub-*.json` are gitignored intermediates — if hub/ looks outdated, regenerate from master-hub.html
- **Manifest exclude-glob (4th field):** `repos.manifest` lines accept an optional 4th `|exclude-glob` field — one or more SPACE-SEPARATED shell globs of skill-dir names to skip — for repos whose `skill_source` dir mixes end-user and unwanted skills. Used by: `rea` (drops 4 `rea-*` maintainer skills) and `agent-browser` (drops 8 Vercel-internal skills, keeping only `core`). Threaded through all three sync points: `install.sh`, `scripts/update.sh`, `scripts/update.ps1`. `install-platform.sh` is unaffected (it copies the repo's own `skills/`, never the manifest cache). It's EXCLUDE-only (no include) — a newly-added upstream skill is admitted by default until added to the list.
- **REA is skill + MCP server (two-part):** wiring the manifest installs only the `reverse-engineer-anything` skill. Its tools are no-ops until the user runs `npx rea-agents setup` (registers the REA MCP server; native targets also need Ghidra/IDA/Hopper). AgentMaster must NOT auto-run setup — it writes MCP config and installs software. The routing row tells the agent to prompt the user if a REA tool call comes back unregistered.

### Domain-layer note (important)
The `claude-skills` repo (alirezarezvani/claude-skills) is a **plugin-of-plugins**: its domain dirs (`engineering-team`, `marketing-skill`, `c-level-advisor`, `finance`, `product-team`, `project-management`, `ra-qm-team`, `business-growth`) are bundles nested 2-3 levels deep (`<dir>/skills/<skill>/SKILL.md` or `<dir>/<subplugin>/skills/<skill>/SKILL.md`) — the flat, one-level installer can't consume them, so `skill_source=.` only ever installed `loop-library`. The routing table used to point business-domain categories at these bundle names, which never resolved to an installed skill. **Fixed by repointing the business-domain layer to the loaded `anthropic-skills:*` plugin** (marketing→running-marketing, sales/growth→executing-sales, product→building-product, strategy→gtm-foundations, finance→setting-pricing+xlsx, compliance→compliance-handling). Coverage is honest-but-thin for finance (no valuation/DCF skill), project-management (no Jira/scrum skill), and regulated compliance (no FDA/ISO/MDR skill) — the routing rows say so. To get deeper business skills later, wire the flat claude-skills subsets (e.g. `marketing-skill/skills`, `ra-qm-team/skills`) as curated manifest lines — but they overlap heavily with anthropic-skills.

### Project doc spine + scaffolding
Mature repos in this workspace share a 4-file spine: `README.md` + `AGENTS.md` +
`CLAUDE.md`(`@AGENTS.md`) + `PROJECTLOG.md`. `PROJECTLOG.md` is the canonical name
(4 repos vs 2 with `PROJECT_LOG.md`) and follows a fixed template: STATUS
(current/ongoing/pending/blocked/done/decisions/verification) then REFERENCE
(what-it-is/stack/data-model/loop/env/commands/conventions).

`/agent-master scaffold` reports which spine files the current project is missing;
`scaffold apply` creates them from `scripts/templates/*.tmpl` (never overwrites,
substitutes project name + date). The orchestrator also runs a report-only scaffold
check once per session and *suggests* (never auto-writes) the missing files. Scripts:
`scripts/scaffold.sh` + `scripts/scaffold.ps1`; templates in `scripts/templates/`.

### Context files across the workspace
`AGENTS.md` (dup: lowercase `agents.md`) is the real context; `CLAUDE.md` is a one-line
`@AGENTS.md` import that never drifts. `convert.sh` does NOT manage any of these three —
they are hand-maintained. Backfilled `CLAUDE.md` pointers into AgentMaster, Content-Wiz,
Email-Automator, cybersecurity-academy (2026-09-09); a global `~/.claude/CLAUDE.md` and
project memory under `~/.claude/projects/.../memory/` were also seeded.
